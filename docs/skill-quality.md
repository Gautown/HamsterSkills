# 技能级质量门槛（skill gate）

> 一句话：仓库级门槛决定「抓不抓这个仓」，技能级门槛决定「仓里的每个 SKILL.md 上不上站」。
> 2026-10 上线实测：6236 个候选技能淘汰 1441（-23%），远端保留 4795 条
> （站内另有 ~30 条本地手写技能，不经过此门槛）。

## 三层判定体系

| 层 | 作用于 | 实现 | 判定码 |
|---|---|---|---|
| 发现 | 仓库（topics 搜索) | `github-skills.ts` discoverRepos | — |
| 仓库级 | 整个仓库 | `src/lib/triage.ts`（`judgeMetadata` / `judgeProbe`） | R1-R10 / S1-S8 / Q1-Q3 |
| **技能级** | **单个 SKILL.md** | **`src/lib/skill-quality.ts`（本文件）** | **SK1-SK4** |

技能级判定在 loader 的逐技能循环里执行，**发生在写入 store 与技能清单之前**。
被拒技能的完整链路后果：

- 不生成页面（五语言都不产）
- 不进 `skills-index.json`（搜索/首页加载不含它）
- 不进 `_manifest.json` → **AI 分类不会为它花钱**
- 不进站内聊天索引

## 规则定义

| 码 | 规则 | 边界语义 |
|---|---|---|
| SK1 | 正文（去 frontmatter 后的 Markdown）字符数 < `minBodyChars` | 严格小于；恰为下限通过 |
| SK2 | `frontmatter.description` 缺失/空白/非字符串（`requireDescription` 开启时） | trim 后判空 |
| SK3 | 与先收录的技能同 sha，或规范化描述完全相同 | 保首个；描述 <30 字符不参与判重 |
| SK4 | 仓内未通过 SK1+SK2 的占比 **严格大于** `repoJunkRatio` → 整仓剔除 | 恰好 90% 不剔除（避免阈值附近来回横跳） |

判定顺序：SK1 → SK2（正文过薄时不再重复报告描述问题）；
整仓决策在全部单条判定完成后、提交之前执行，SK3 在提交时逐条判。

## 阈值来源（不是拍脑袋）

2026-10-21 对全部 6181 条在站技能做了分布分析（缓存 body 全量统计）：

| 信号 | 数量 | 结论 |
|---|---|---|
| 正文 p25 / p50 | 2483 / 5161 字符 | 下限画在 2000：低于它的 1316 条中集中了全部问题样本 |
| 正文 <300 | 263 | 符号链接指针（正文就是一行 `"../x/SKILL.md"`）、"First skill" 测试残留、模板文件 |
| 无 frontmatter.description | 298 | 描述会退化成目录名拼接（如 "Cmd Cs Aeo"），一律不上站 |
| 跨仓纯重复 | ~26 | 同 sha（第三方抄 anthropics 原件）或同描述 |
| 仓内失效率 >90% | 7 仓 / 283 条 | alirezazvani/claude-skills 186/186 全是符号链接指针 |

上线首轮实测淘汰分解（本地构建、发现缓存刷新后）：

| 码 | 数量 | 说明 |
|---|---|---|
| SK1 正文过薄 | 1088 | 含全部符号链接指针与测试残留 |
| SK2 无描述 | 39 | 与 SK1 重叠后剩余（先报 SK1） |
| SK3 跨仓重复 | 20 | 全量验证过：anthropics 原件的第三方转载、多平台变体副本、`tests/golden/` 测试夹具 |
| SK4 整仓剔除 | 294 | 7 个近全废仓，全部「保留 0」 |
| **合计** | **1441** | 保留 4795（远端）|

淘汰数以「文件」计：同一 id 的多份薄文件会被各自记录（它们确实各自被判定并淘汰），
但**提交侧同一 id 只可能出现一次**（构建后清单已验证 0 重复 id）——这是本门槛
与旧版「id 占用」跳过语义的衔接点，见 `github-skills.ts` 提交循环里的守卫注释。

## 配置

`content.config.ts` 读取以下环境变量（.env / CI Secrets 均可）：

| 变量 | 默认 | 含义 |
|---|---|---|
| `SKILLS_SKILL_GATE` | （开） | 设 `0` 关闭全部技能级判定 |
| `SKILLS_MIN_BODY_CHARS` | `2000` | 正文下限；设 `0` 关闭该项 |
| `SKILLS_REQUIRE_DESCRIPTION` | （开） | 设 `0` 允许无描述上站 |
| `SKILLS_REPO_JUNK_RATIO` | `0.9` | 整仓剔除比例；设 `0` 显式关闭该项 |

注意 `SKILLS_REPO_JUNK_RATIO=0` 被定义为**关闭**而不是「有垃圾就剔除」——
后者的字面歧义会瞬间清空站点，运维意图必须无歧义（见 `readOptionalRatio`）。

调整阈值之后的验收方式：构建 → 看日志里 `技能级门槛：淘汰 N 条(...)`
→ 与 `.cache/skills-remote/_skill-gate.jsonl` 逐条核对原因。

## 日志与审计

- `.cache/skills-remote/_skill-gate.jsonl`：每行一个被淘汰技能
  `{repo, id, sha, code, reason, bodyChars}`；每轮构建无条件重写
- `npm run audit` 输出 `=== skill gate ===` 一节：按码计数 + SK4 仓库名单
  （观察项，不参与 CI 失败判定）

## 设计纪律

1. **证据不足不判 SKIP**：只判能用现有字段正面证伪的；拿不准一律放行
   （与 `triage.ts` 同一纪律）。
2. **纯函数 + 单测**：`scripts/skill-quality.test.mjs` 钉死全部边界语义；
   判定类故障的特征是「静默少东西」，只能靠单测在构建前拦住。
3. **可以一键回退**：关闭门槛重跑构建，被拒内容随缓存立即回来
   （拒绝不删缓存，与 triage 的决策一致）。
4. **离线工具不受影响**：`npm run triage` 不传 `skillGate`，行为与规范一致。

## 非目标（本版）

- 不做单个模板/占位符痕迹的文本判定（假阳性过高，靠 SK1/SK2 间接覆盖）
- 不做「仓内失效率 50%-90%」的整仓剔除（逐条判定更精准，不连坐好技能）
- 不改变本地手写技能（`src/content/skills/`）——门槛只作用于远端聚合
